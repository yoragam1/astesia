# Phase 4: QUALITY
**Objective:** Audit, test, and act as a gateway before deployment.

---

## 1. Input Analysis

- [ ] Read Acceptance Criteria from `.astesia/brd.md`.
- [ ] Read source code generated by Engineering.
- [ ] Read `.astesia/architecture.md` for architectural expectations.
- [ ] Verify `astesia-state.json` shows `layer_statuses.engineering` = `done`.
- [ ] Set `layer_statuses.quality` to `in-progress`.

## 2. Test Generation & Verification

- [ ] Verify Engineering's unit tests exist and pass.
- [ ] Verify code coverage meets **80% baseline** (Quality Rule #4).
- [ ] Generate **Integration Tests** covering cross-module interactions.
- [ ] Generate **E2E Tests** (if applicable) using Playwright or equivalent.
- [ ] Map every test back to a specific Acceptance Criterion from the BRD (Quality Rule #2 — Strict Traceability):

```
| Test File | Test Name | BRD Acceptance Criterion |
|-----------|-----------|-------------------------|
| user.service.test.ts | should create user | Feature 3.1 AC #1 |
```

## 3. Architectural Audit

- [ ] **Programmatic Enforcement:** Run `architectural-linter` to programmatically detect N+1 queries and controller-DB breaches.
- [ ] **Layered Architecture Compliance:**
  - No business logic in controllers/routes.
  - No database calls outside the repository layer.
  - Dependency direction: Controller → Service → Repository (no reverse imports).
- [ ] **Modular Design:**
  - Each domain module is self-contained (routes + schema + service + repo).
  - No circular dependencies between modules.

## 3.5. Anti-Bloat Audit (Ponytail Review)

- [ ] **Dependency Audit:** Check if any installed 3rd-party dependency could be replaced with Native/Stdlib.
- [ ] **YAGNI Check:** Identify any abstractions (Interfaces, Factories, base classes) that only have 1 implementation. Tag them with `delete:`.
- [ ] **Code Shrinking:** If a 20-line block can be replaced by a 1-line native function, flag it with `shrink:`.

## 4. Security Audit (Quality Rule #3 — Ruthless)

- [ ] **Hardcoded Secrets:** Scan for API keys, passwords, tokens in source code. Must use ENV.
- [ ] **Input Validation:** All API endpoints validate input with Zod/Joi schemas.
- [ ] **SQL Injection:** Verify parameterized queries (Drizzle ORM handles this, but check raw queries).
- [ ] **XSS/CSRF:** Check frontend output encoding and CSRF protection.
- [ ] **Auth Boundaries:** Verify that protected routes enforce auth middleware.
- [ ] If ANY security flaw is found → **FAIL immediately**, return to Engineering with detailed report.

## 5. Documentation Sync Audit (Quality Rule #5)

- [ ] Every source file has an accurate **Header Doc** (Engineering Directive #19).
- [ ] `.astesia/system-map.md` is synchronized with actual code state.
- [ ] If docs are stale/missing → **FAIL**, return to Engineering.

## 6. Database Performance Audit (Quality Rule #6)

- [ ] Check for **N+1 queries** in repository layer.
- [ ] Check for **unbounded SELECT *** (must use `.select({...})` with specific columns for list endpoints).
- [ ] Verify **batch operations** are used where applicable.
- [ ] Verify **index usage** on frequently queried columns.
- [ ] If anti-patterns found → **FAIL**, return to Engineering with remediation instructions.

## 7. Verdict & Handoff

### If ALL checks pass:
- [ ] Generate `.astesia/qa-test-plan.md` with test results summary.
- [ ] Update `astesia-state.json`:
  - Set `layer_statuses.quality` to `done`.
  - Set `current_layer` to `devops`.
  - Add history entry: "Quality audit passed — all tests green, no security issues."
- [ ] Inform the user of the transition to DevOps.

### If ANY check fails:
- [ ] Check `astesia-state.json` history for previous failed attempts.
- [ ] **Retry Limit Check:** If the Quality layer has failed and returned to Engineering 3 times already:
  - **ESCALATION:** Set `status` to `halted` in `astesia-state.json`.
  - Add history entry: "Quality audit FAILED 3 times. Escalating to human for manual intervention."
  - **HALT PIPELINE** and notify the user that automated remediation has failed.
- [ ] If under the limit (0-2 previous fails):
  - Generate detailed **Error Report** listing every failure.
  - Update `astesia-state.json`:
    - Set `layer_statuses.quality` to `failed`.
    - Set `current_layer` to `engineering`.
    - Add `blocking_issues` entries with failure descriptions.
    - Add history entry: "Quality audit FAILED — returned to Engineering."
  - **DO NOT proceed to DevOps.**

## Fail Conditions (Return to Engineering)

- ❌ Code coverage < 80% → Return with coverage report.
- ❌ Security flaw detected → Return with security audit report.
- ❌ Architecture violation found → Return with specific violation details.
- ❌ Missing/stale Header Docs → Return with list of files needing documentation.
- ❌ Database performance anti-pattern → Return with query remediation plan.

## Expected Output

```
.astesia/
├── qa-test-plan.md            # Test results & audit summary
└── astesia-state.json         # Updated: current_layer = "devops" (pass) or "engineering" (fail)
```
